# Cinderline

Персональная тёмная тема для Zed, Neovim и VS Code: нейтральный тёмно-асфальтовый фон, мягкий белый и серебристый текст с приглушёнными оранжевыми акцентами. Цвета текста и акцентов точно повторяют палитру `~/.config/oh-my-posh/cinderline.omp.json`.

**Asphalt & silver.** Фоны строго серые, без синего и коричневого оттенков. Палитра ограничена семью цветами prompt-темы, без дополнительных светлых или тёмных вариантов. Фоны в Oh My Posh не заданы, поэтому сохранены поверхности Zed; подсветки используют прозрачные версии исходных цветов.

**Открыть цветовой эскиз:** [preview.html](preview.html) — локальный HTML, работает без интернета и сервера. Цвета берутся из самой темы; это схематичная иллюстрация, не скриншот Zed.

## Включить в Zed

1. Помести `themes/cinderline.json` в `%APPDATA%\Zed\themes\` на Windows.
2. Перезапусти Zed, если тема ещё не появилась в списке.
3. Открой палитру команд (`Ctrl+Shift+P`), выполни **theme selector: toggle**, выбери **Cinderline** и нажми Enter.

Для постоянного тёмного оформления достаточно этого поля в пользовательском `settings.json`:

```json
{
  "theme": "Cinderline"
}
```

Добавь поле в существующий объект настроек. На macOS и Linux каталог темы — `~/.config/zed/themes/`.

## Включить в Neovim

Скопируй [colors/cinderline.lua](colors/cinderline.lua) в подкаталог `colors` своей конфигурации Neovim (создай его, если нужно). Обычно это `%LOCALAPPDATA%\nvim\colors\` на Windows или `~/.config/nvim/colors/` на Linux и macOS. Точный каталог конфигурации покажет `:echo stdpath('config')`.

В терминале с поддержкой True Color выполни `:set termguicolors` и `:colorscheme cinderline`. Чтобы сохранить выбор, добавь в `init.lua`:

```lua
vim.opt.termguicolors = true
vim.cmd.colorscheme("cinderline")
```

Тема работает без плагинов. Она оформляет обычный синтаксис, группы Tree-sitter и LSP, диагностику, поиск, diff и 16 ANSI-цветов встроенного терминала. Для быстрого сравнения с Zed открой `examples/room.ts`, найди `Room` и выдели несколько строк.

## Включить в VS Code

Собери и установи локальное расширение (нужны Node.js и команда `code`):

```powershell
cd vscode-theme
npx --yes @vscode/vsce package --no-dependencies --out cinderline.vsix
code --install-extension cinderline.vsix
```

Выбери **Cinderline** через **Preferences: Color Theme** (`Ctrl+K`, затем `Ctrl+T`). Тема оформляет интерфейс, синтаксис (TextMate и семантические токены), терминал, диагностику и Git diff.

После изменения исходной темы Zed запусти `python tools/vscode.py` из корня репозитория, чтобы обновить тему VS Code, затем пересобери и переустанови расширение. Команда `python tools/vscode.py --check` проверяет, что сгенерированный файл соответствует исходнику.

## Дизайн

Оранжевый сосредоточен в небольших акцентах. Основные заливки и границы нейтрально-серые. Выделение текста и совпадения символов используют полупрозрачное серебро, поиск — тёплые заливки. Окно непрозрачное, поэтому обои не меняют контраст. Git diff использует яркие маркеры и более спокойные заливки.

Тема включает 52 синтаксические категории, 24 ANSI-цвета терминала, состояния интерфейса и диагностики, палитру совместной работы, minimap, отладчик и индикаторы Vim/Helix. Оформление доступно в пределах возможностей тем Zed; форма окон, отступы и шрифты задаются самим редактором и его настройками.

## Читаемость

Расчёт относительной яркости sRGB на фоне редактора:

| Элемент | Контраст |
| --- | ---: |
| Основной текст редактора | 12,56:1 |
| Оранжевый акцент | 7,34:1 |
| Комментарии | 8,42:1 |

`tools/audit.py` проверяет 1341 сочетание цветов с учётом прозрачности:

- обычный код, комментарии, одиночные выделения на активной строке и основной текст интерфейса — минимум **4,5:1**;
- подсказки-продолжения, dim ANSI-цвета и проверенные сочетания нескольких подсветок — минимум **3:1**;
- ANSI black, декоративные линии и отключённые элементы не относятся к основному читаемому тексту.

Дополнительно проверяются цвета файлов на обычном фоне, при наведении и выделении, заметность Git-маркеров и заливок, согласованность общих и `version_control.*` токенов и точное соответствие палитре prompt-темы. Как в Oh My Posh, изменённые файлы серебристые, а удаления и конфликты используют один красный: различать эти состояния нужно также по значкам и тексту, не только по цвету.

Контраст — технический ориентир; комфорт зависит также от яркости экрана, освещения и размера шрифта. Для первого просмотра подойдёт привычный моноширинный шрифт размером 14–16 и умеренный межстрочный интервал.

## Посмотреть в редакторе

Открой `examples/room.ts`, `examples/room.py` и `examples/notes.md`. В них есть типы, строки, числа, комментарии, регулярное выражение, Markdown и встроенные блоки JSON/diff.

Для визуальной проверки выдели несколько строк, найди `Room`, открой автодополнение, дерево файлов и терминал. Проверь также настоящий Git diff в своём проекте. После первого просмотра можно подстроить теплоту и яркость по скриншоту именно твоего Zed.

### Если статусы не видны

Тема задаёт цвета, но не включает функции редактора. Проверь соответствующие поля в своих настройках Zed:

```json
{
  "project_panel": {
    "git_status": true,
    "show_diagnostics": "all"
  },
  "tabs": {
    "git_status": true,
    "show_diagnostics": "all"
  }
}
```

Диагностика требует работающего language server: тема не может сама обнаружить ошибки. В версиях Zed, поддерживающих `project_panel.diagnostic_badges` и `project_panel.git_status_indicator`, их можно включить дополнительно для обозначений, не зависящих только от цвета.

Скрытый файл (например, `.env`) не обязательно Git-ignored. В проверенной актуальной реализации Zed цвет имени дерева определяется Git-статусом и ignored-состоянием; токен `hidden` не гарантирует отдельного затемнения всех dotfiles. Git-статус также может иметь приоритет над ignored. Превью показывает образцы цветов состояний, а не точное расположение значков диагностики в Zed.

## Палитра для системы

В `palette.css` сохранены семантические переменные для переноса оформления на другие приложения.

Рекомендуемое распределение: большие поверхности — `base`/`editor`; меню — `elevated`; обычный текст — `text`; второстепенный — `text-muted`; небольшой яркий акцент — `orange`; крупные активные области — графитовый `selected`.

На сплошных оранжевых кнопках используй тёмный текст `on-accent`. Терминальные ANSI blue/cyan/magenta остаются серебристо-серыми; yellow — оранжевый `#D99565`. Для red/green/yellow яркие и dim-варианты используют те же точные цвета, без осветления и затемнения. Часть стандартной цветовой семантики терминала намеренно упрощена. Имена `slate`, `sea-glass`, `mauve`, `amber` и `peach` сохранены для совместимости. `copper`, `copper-hover` и `clay` — CSS-псевдонимы.

## Проверка и обновление превью

Python 3, без зависимостей:

```powershell
python tools/audit.py
python tools/preview.py
```

Источник токенов — `themes/cinderline.json`; точная палитра Oh My Posh закреплена в `tools/audit.py`. После редактирования обнови соответствующие токены `palette.css` и пересоздай превью. Аудит дополнительно обнаруживает повторяющиеся JSON-ключи, неверные HEX-цвета, оттенки вне палитры (кроме тёмных нейтральных поверхностей) и цвета CSS-палитры, отсутствующие в теме.

JSON также проверен по [официальной схеме](https://zed.dev/schema/themes/v0.2.0.json); имена полей сверены с исходниками установленного Zed 1.28.1. Публичная схема отстаёт от набора полей редактора, поэтому новые поля проверяются по исходникам отдельно.
