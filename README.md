# Cinderline

Тёмная тема для Zed, Neovim и VS Code. Нейтральный асфальт `#101010`, графитовый редактор `#151515`, мягкий белый текст `#D6D6D6` и медный акцент `#D99565` остались основой Cinderline. Новые оттенки отделяют роли в коде и Git, не окрашивая фон интерфейса.

[Открыть автономное превью](preview.html) · [Глобальная палитра](palette.json) · [CSS-переменные для браузера](palette.css)

## Синтаксис

Ключевые слова медные, строки шалфейные, числа терракотовые. Именованные константы вроде `TABLIST` в TSX — ярко-оранжевые, в тон предупреждениям. Имена функций светло-медные, типы глиняные, имена полей совпадают по цвету с основным текстом, параметры — льняного оттенка.

В Zed явно задано прямое начертание для каждой синтаксической роли, включая комментарии, документацию и Markdown `*emphasis*`. `**strong**` остаётся жирным. Покрыты Tree-sitter и имена, которые используют стандартные правила семантических токенов Zed: определения классов и интерфейсов, методы, пространства имён, декораторы, поля enum и другие. Какие роли доступны в конкретном файле, зависит от грамматики и language server.

## Git: что означает каждый цвет

| Роль палитры | Цвет | Где искать |
| --- | --- | --- |
| `added` | `#A5C493` · лишайник | Новые неотслеживаемые (`U`) и добавленные в индекс (`A`) файлы, добавления в diff |
| `modified` | `#D99565` · основная медь | Изменённые файлы (`M`) и маркеры изменений |
| `deleted` | `#DD9387` · терракота | Удаления (`D`), удалённые строки и слова |
| `renamed` | `#D5B67F` · латунь | Представления, в которых редактор выделяет переименование |
| `conflict` | `#CA9ABD` · вереск | Неразрешённые конфликты (`!`) |
| `ignored` | `#737373` · графит | Файлы, игнорируемые Git |

Имена в дереве, индикаторы, вкладки и diff получают цвета из одних ролей: `created` и `version_control.added` ссылаются на `added`. У строк diff спокойная заливка, у изменённых слов — более плотная. Для полых маркеров отдельно заданы фон и граница.

**Git и диагностика видны одновременно.** В дереве Zed 1.30.2 Git задаёт цвет имени, а диагностика — цвет отметки и счётчика рядом. У изменённого файла с ошибкой имя медное, счётчик терракотовый (`#DD9387`); у нового файла с предупреждением имя зелёное, счётчик ярко-оранжевый (`#F4AE74`). Для счётчиков задай `"show_diagnostics": "all"` и `"diagnostic_badges": true` в `project_panel`.

**Если имя и Git-индикатор различаются:** для имени приоритет такой: конфликт → удаление → изменение → добавление → ignored. Каталог агрегирует статусы содержимого: при наличии изменённого и нового файла имя может быть медным, а точка — зелёной. Это поведение [имени](https://github.com/zed-industries/zed/blob/610ea4b8de1c6e887f03563f067278002f41256e/crates/editor/src/items.rs) и [индикатора](https://github.com/zed-industries/zed/blob/610ea4b8de1c6e887f03563f067278002f41256e/crates/project_panel/src/project_panel.rs) самого Zed. Для проверки файла сравни с `git status --short`.

Для отображения статусов включи `project_panel.git_status`, `project_panel.git_status_indicator` и `tabs.git_status`. Для пословной подсветки — `word_diff_enabled`. Параметр `git.git_gutter: "tracked_files"` управляет полем редактора, а не цветом имени: у нового файла до `git add` может быть зелёное имя без полосы у строк.

## Глобальная палитра

**Редактируй [palette.json](palette.json).** В `colors` хранятся базовые HEX, в `roles` — назначения для текста, поверхностей, синтаксиса, Git, диагностики и ANSI. Роль ссылается на базовый цвет или другую роль. Запись `added/27` — это цвет `added` с альфой `0x27` в формате `#RRGGBBAA`, а не 27 процентов.

- **Браузер:** подключи `palette.css` и используй `var(--cinderline-editor)`, `var(--cinderline-text)`, `var(--cinderline-focus)` или `var(--cinderline-modified)`. Для тёмной надписи на акцентной кнопке предусмотрен `--cinderline-on-accent`.
- **Терминал:** `editor` — фон, `text` — текст, `focus` — курсор, `selection` — выделение. Слоты 0–7 — `ansi-black` … `ansi-white` в порядке black, red, green, yellow, blue, magenta, cyan, white; 8–15 — `ansi-bright-*`. Есть также `ansi-dim-*`. Стандартные слоты blue и cyan используют тёплые медные и бронзовые оттенки.
- **Новый порт:** используй смысл роли, а не её нынешний HEX. Например, цвет изменённого файла бери из `modified`, а не из `orange`. Для приложений без альфа-канала накладывай полупрозрачный цвет на реальный фон (пример — экспорт Neovim).

Сборка из корня, Python 3.10+, без внешних зависимостей:

```sh
python tools/build.py          # Zed, VS Code, Neovim, CSS и автономное превью
python tools/build.py --check  # обнаружить устаревшие экспорты без записи
python tools/audit.py          # контраст с учётом альфы, начертание и Git-статусы
```

Аудит проверяет код на фоне редактора, активной строки и одиночных подсветок (обычный текст ≥ 4,5:1), а также наложение выделений и изменённого слова на строку diff (≥ 3:1). Для имён файлов проверяются обычный фон, наведение и выбор; отдельно проверяется, что изменённое имя не сливается по цвету с неизменённым.

## Установка

- **Zed:** скопируй [themes/cinderline.json](themes/cinderline.json) в `%APPDATA%\Zed\themes\` на Windows или `~/.config/zed/themes/` на Linux/macOS. Выбери **Cinderline** через `theme selector: toggle`. После новой сборки обнови установленную копию.
- **Neovim:** скопируй [nvim-theme/cinderline.lua](nvim-theme/cinderline.lua) в `colors/` внутри `stdpath('config')`. Выполни `:set termguicolors` и `:colorscheme cinderline`.
- **VS Code:** в `vscode-theme/` выполни `npx --yes @vscode/vsce package --no-dependencies --out cinderline.vsix`, затем `code --install-extension cinderline.vsix`. Выбери **Cinderline** через **Preferences: Color Theme**.

В VS Code настроены и TextMate, и семантические токены. При отключённой семантике грамматика TSX не различает константу и обычную переменную внутри именованного импорта. В Neovim схема поддерживает Tree-sitter и LSP, а при наличии Neo-tree и Gitsigns применяет те же Git-цвета в дереве файлов и diff. Плагины для самой схемы не требуются.

Для визуальной проверки открой [TypeScript](examples/room.ts), [Python](examples/room.py) и [Markdown](examples/notes.md). [preview.html](preview.html) показывает те же цвета на образцах кода, Git-статусов и diff и работает без сервера.
